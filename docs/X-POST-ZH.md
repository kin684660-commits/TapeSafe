# TapeSafe：把团队审批规则做成真正的链上电路

我带着黑客松项目 TapeSafe 来了：支持 TapeOut，支持 X Layer！

做这个项目，是因为团队审批里有些问题，光看“几个人点了同意”还不够：发起人能不能给自己投票？哪些成员必须签字？紧急冻结以后，已经凑够票数的请求还能不能通过？

TapeSafe 把这些规则编译成一份真实的 TapeOut NAND 电路。最多五名成员，支持最低有效票数、发起人不计票、必签成员和紧急冻结。输入审批状态，电路就给出通过或拒绝的结果。

这份规则电路一共用了 74 个 NAND，19 位输入、1 位输出、0 个 LATCH，网表只有 518 字节。两名有效成员批准可以通过；票数不足、发起人自批凑票、缺少必签成员，或者开启紧急冻结，都会被拒绝。

CPU #267，Circuit #1，已完成流片。处理器创建、74 个 NAND 单元铸造和电路流片的三笔主网交易，都已核对。处理器发行上限 210,000，单个晶体管铸造价格 0.000066 OKB，协议费和 Gas 另付。

打开产品就能体验：在电路实验室切换“两票通过、自批无效、紧急冻结”等场景，看到输入和结果如何变化；在链上核验页面，不用连接钱包，就能查看真实合约、电路规格、持有人和四组主网求值结果。页面通过两个独立 RPC，在同一区块交叉核对这些数据。

仓库里也整理了部署收据、完整网表、核验命令和测试记录。本地测试覆盖全部 524,288 组输入，主网核验覆盖四组代表场景，两部分证据分别保留。

这次提交完成了处理器和规则电路的主网部署。金库执行器已有代码与测试，尚未部署；电路目前只判断审批规则，不执行转账。项目仍是未审计原型，底层协议合约可升级。下一步，我想把这份规则电路接入完整的团队金库流程，让审批与执行真正连起来。

TapeSafe 的目标很直接：让团队审批不止是一串签名，还能看清楚到底按什么规则通过。
